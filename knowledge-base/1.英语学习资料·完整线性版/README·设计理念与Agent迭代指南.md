# 英语学习资料·完整线性版｜设计理念与 Agent 迭代指南

> **文档用途**：供后续维护、扩充或迭代本套资料的 AI Agent 与作者快速对齐核心设计思路、教学原则、排版规范与防退化红线。**动手修改任何章节或题库前，请先通读本指南。**

---

## 一、这套资料的核心定位

1. **目标读者**：**真正的英语 0 基础中文自学者**（在 Obsidian 中线性阅读，配合浏览器离线刷题），同时兼顾**同等学力申硕七个月备考**的首轮节奏，作为 `2.同等学力申硕英语·考试强化` 的前置地基。
2. **最高设计目标（第一性原理）**：
   > **极大减轻读者的心智负担——让读者从 0 听懂知识，并且由资料自动帮读者筛出重点、整理记忆笔记，绝不让读者自己在一大段文字里焦虑“哪些该背、哪些只需理解”。**

基于这一目标，全书把学习过程严格拆成四层分工：

| 层次 | 载体 | 读者心智定位 | 设计要求 |
|---|---|---|---|
| **1. 听课理解** | 章节普通正文 | 读顺、听懂即可，**不要求逐字背诵** | 分段拆块、先讲人话、逐层搭桥、配齐中文译文 |
| **2. 课堂敲黑板** | `==高亮==` + `> [!important] 记笔记` / `> [!warning] 易错避坑` | 看到即知道“这里要记下来/别踩坑” | 克制标注，只标最核心的规则、公式与易错点 |
| **3. 课后自动笔记** | 每章末尾 `## 本章核心记忆笔记` | 课后强化记忆与日后快速回想的唯一入口 | 固定三段式（核心必背 / 高频易错避坑 / 合上书自检） |
| **4. 闭环刷题验收** | `强化题目/交互刷题.html`（由 31 份 MD 自动构建） | 逐题自测、即时核对、自动沉淀错题 | 离线可用、每题独立显隐答案、首轮必做筛选、C 组自动计分与全局错题本 |

## 三、正文写作与排版规范（必须遵守）

### 1. 分段拆块，严禁“文字墙”
- **规则**：解释性正文每段控制在 **1–2 句话（不超过 ~120–150 字）**，严禁超过 200 字不换行。
- **原则**：只要切换了一个子概念（例如从“单复数”切到“冠词”，再切到“可数/不可数”），就必须**换行、分点（`- `）或拆小标题**，让大脑可以一块一块独立消化，而不是被迫一口气读完一整坨。

### 2. 正文“敲黑板”标注与提醒框规范（适配 Obsidian，读者核心偏好，必须保留）

本套资料把“老师讲课提醒”固定为 **`==高亮==` + 四类 Obsidian Callout 提醒框**。这是读者明确高度认可的减负设计，**后续任何新增章节、扩充内容或重构都必须延续这套提醒框体系，绝不可退化回纯文字或普通引用块**：

- **`==高亮==`**：仅用于必须记住的**核心规则、公式或反直觉铁律**；每小节克制使用 1–3 处，**严禁高亮整段话**（满屏高亮等于没有高亮）。
- **四类标准 Callout 提醒框**：

| Callout 语法 | 固定用途（对应课堂场景） | 使用要求 |
|---|---|---|
| `> [!important] 记笔记` | **核心提炼**：放在每个核心大节末尾，替读者总结“这一块只背这 1–3 句就够了” | **每章必有**，要点极简，直接可当笔记背 |
| `> [!warning] 易错避坑` | **母语负迁移与高频坑点**：专门拦住最容易错的地方（如单数可数名词不能裸奔、不可数名词不加 `s`） | 优先用 `✅ ... / ❌ ...` 对比，一眼看懂错在哪 |
| `> [!tip] 小贴士`（或 `零基础省力口诀` / `学习节奏提示`） | **省力技巧与记忆钩子**：如语音口诀、查词技巧、长章分次阅读建议、记忆法（如 `FANBOYS`） | 简短实用，降低畏难情绪 |
| `> [!note] 预告`（或 `说明`） | **先修边界安抚**：提前说明“这里先混个眼熟，完整规则在第 XX 章展开” | 防止 0 基础在未学概念处卡壳 |

示例模板：
```markdown
> [!important] 记笔记
> - **核心结论 1**：一句话说清规则 + 1 个最短例句。
> - **核心结论 2**：一句话说清边界。

> [!warning] 易错避坑
> - ✅ `I have a dog.`（单数可数名词前有限定词）
> - ❌ `I have dog.`（单数可数名词不能裸奔）

> [!tip] 小贴士
> 记不住复杂术语时，先背 1 句顺口的锚定例句，做题时拿例句套就行。
```

### 3. 章末《本章核心记忆笔记》固定模板
每一章（含 `00·语音与拼读起步`）在 `## 本章强化与验收` 之前，必须包含统一结构的 `## 本章核心记忆笔记`（并同步更新章首 `## 本章目录`）：
1. **核心必背（只记这几条）**：3–6 条精炼规则（`==关键词==` + 1 句最典型的锚定例句）。
2. **高频易错避坑**：2–4 组 `✅ ... / ❌ ...` 对比。
3. **合上书自检（2–3 句话通关）**：2–3 个口头/心中速答小问题，答案用 `<details>` 折叠。

### 4. 教学严谨度与 0 基础友好底线
- **严禁先修倒挂不加提示**：若早期章节例句不得不出现尚未学过的语法现象（如第 02 章出现 `There are`、第 07 章提及短语动词及物性、第 20/28 章涉及倒装），必须明确标注**“这里先认出整句意思即可，完整规则在第 XX 章展开”**，绝不让 0 基础读者自我怀疑。
- **全中文译文覆盖**：正文所有例句、表格示例、章内自测选择题/判断题，都必须附带清晰中文译文（如 `（句意：……）`），不能把生词量变成理解语法的拦路虎。
- **反“伪口诀”与学术严谨性**：不要为了图省事写绝对化错误口诀（例如：`unless` 并非绝对禁止 `not`；`while` 不只接进行时；`-ing/-ed` 不机械等于“物/人”；`could` 可用于过去感官动词；宾语从句客观真理或仍成立的事实时态可不回退；限制性/非限制性定语从句不能仅靠“去掉后句子是否完整”机械判断）。
- **保留分层标签**：标题旁的 `【必学】`、`【识读即可】`、`【选做·综合复盘】` 以及题库里的 `【必做】`、`【识读必做】`、`【选做】` 是七个月首轮减负的关键机制，迭代时不可随意删改。

### 5. 交互刷题网页设计规范（`交互刷题.html`，读者高度认可，必须保持）

`强化题目/交互刷题.html` 是这套资料练习体验的核心载体（由 `编排记录/生成交互练习HTML.py` 自动生成），后续迭代**必须保留以下全部设计特性**：

- **零依赖离线单文件架构**：不依赖任何外部 CDN、字体或本地服务器，直接通过 `file://` 双击或由 Obsidian 点击相对链接即可离线秒开。
- **Obsidian 单章一键直达机制**：通过 `强化题目/章节入口/第01章.html ~ 第31章.html` 轻量跳转页自动定向至 `../交互刷题.html#ch=XX`，确保每章章末 `## 本章强化与验收` 的主链接用**纯相对路径**直达对应章节的交互题（MD 练习链接保留作纯文本底稿备用）。
- **低心智负担的交互卡片设计**：
  - **每题独立显隐答案**：默认隐藏答案，每题配备独立输入框（支持按回车展开解析）与 `👁 显示答案 / 🙈 隐藏答案` 按钮，以及当前页一键全部展开/收起。
  - **默认首轮减负筛选**：默认只显示 `⭐ 首轮必做`（自动隐藏选做题），支持切换 `全部题目 / 未自评 / 错题不稳` 与 `A / B / D / C` 分组。
  - **自评计分与全局错题本**：每题支持 `✅ 会了 / ⚠️ 不稳 / ❌ 错了` 三态自评，自动计算 **C 组独立验收实时得分与达标提示**，并将所有错题/不稳题汇入左侧 **📕 全局错题本**。
  - **清爽护眼视觉**：暖白浅色 + 深色护眼模式切换、左侧 4 阶段章节进度条与搜索、可折叠的“练习范围与易错点”抽屉。
- **持久化存储契约（防丢进度）**：
  - 使用浏览器 `localStorage` 本地持久化，**严禁随意修改存储键名**：
    - 刷题进度与输入：`eng_linear_practice_v1`（数据结构 `{ grades: { "01:A01": "ok"|"warn"|"bad" }, inputs: { "01:A01": "..." } }`）
    - 深浅色主题：`eng_linear_theme_v1`
  - 后续若升级 HTML 功能，必须保持对上述键名与数据结构的**向后兼容**，避免覆盖或清空读者已积累的刷题记录。

## 四、绝对不能踩的坑（防退化红线）

1. **严禁再把两份资料直接拼接产生 `## 知识归纳与补充　【同主题复盘】`**：历史上曾因合并旧版资料，导致 22 章出现占篇幅 40%–60% 的重复复盘区，且在重复区里埋藏少数独有知识点。**现已全部融合清理，后续新增知识必须直接写进正文对应小节，绝不允许另起重复复盘块。**
2. **严禁破坏 01–31 章的文件编号与双链**：`章节/`、`强化题目/`、`00·从这里开始.md` 之间通过 Obsidian 双向链接 `[[...]]` 严密互联；若需新增导学或专题，优先放在 `00·...` 或并入现有章节，不要重排 01–31 编号。
3. **严禁直接手改 `强化题目/交互刷题.html` 里的题库数据**：
   - `强化题目/01~31·强化练习·*.md` 才是**唯一数据源**。
   - 修改题目、答案、标签或范围边界时，必须**先改对应的 `.md` 文件**，然后运行：
     ```bash
     python "1.英语学习资料·完整线性版/编排记录/生成交互练习HTML.py"
     ```
     一键重新生成 `强化题目/交互刷题.html`，确保 MD 与 HTML 100% 同步。
   - **题库 MD 格式契约**（解析脚本依赖以下约定，修改时勿破坏）：
     - 题干行格式：`**A01｜【必做】主题名**　题干内容`（题号前缀为 `A/B/C/D + 两位数字`，标签仅限 `【必做】`、`【识读必做】`、`【选做】`）。
     - 答案行格式：`<p><strong>A01</strong>　参考答案与解析</p>`（放在对应分组的 `<details>` 内，与题号严格 1 对 1 对应）。
4. **严禁在“独立表达”题的可用词里直接泄密答案**（如构词法题直接给出派生后的答案词，应给“词根 + 词缀提示”）。
5. **严禁删减或弱化 Obsidian Callout 提醒框体系**：`> [!important] 记笔记`、`> [!warning] 易错避坑`、`> [!tip] 小贴士` 是读者极度依赖的视觉抓手与心智减负机制，迭代改写正文时**不得**把它们改回普通段落或普通 `>` 引用，新增知识点也必须同步配齐对应的提醒框。
6. **严禁退化交互刷题网页或破坏进度兼容性**：不得把章末主练习链接退回纯 MD，不得破坏 `章节入口/第01~31章.html` 跳转机制，不得随意更改 `localStorage` 键名 `eng_linear_practice_v1`（否则会丢失读者已有刷题记录与错题本）。

## 五、迭代完成后的标准验收清单

每次对本套资料做批量修改后，建议运行脚本检查以下 6 项指标，全部归零/达标才算交付：

1. **全库双链断链 = 0**（检查 `00·从这里开始.md`、`章节/*.md`、`强化题目/*.md` 中的 `[[...]]`）。
2. **章内目录锚点错误 = 0**（检查每章 `[[#...]]` 是否与实际标题完全一致且无重名标题）。
3. **无残留 `## 知识归纳与补充` / 旧 `## 本章小结`**，全部 32 章具备 `==高亮==`、Obsidian Callout 提醒框（`[!important]` / `[!warning]` / `[!tip]`）与 `## 本章核心记忆笔记`。
4. **超长正文段（> 200 字，排除表格/列表/折叠答案）= 0**。
5. **所有 `<details>` 与 `</details>` 标签严格配对**。
6. **若改动过练习题**：已重新运行 `编排记录/生成交互练习HTML.py`，且校验 `MissingAns = 0`、`MissingPrompt = 0`。
